# AI-Powered Chat QnA Backend — Startup & Deployment Guide

This guide describes how to run and configure the Spring Boot Backend application from a fresh environment.

---

## 1. Prerequisites

Before starting the backend, make sure you have the following installed on your machine:

* **Java 21** or later (JDK 21)
* **Maven 3.9+** (or use the included Maven wrapper `mvnw` / `mvnw.cmd`)
* **Docker & Docker Compose** (for PostgreSQL with `pgvector`)
* **Google Gemini API Key** (for LLM reasoning & vector embeddings)

---

## 2. Storage Architecture

The backend manages data across three dedicated layers:

1. **PostgreSQL (`pgvector` Table)**:
   - Stores mathematical vector embeddings of document chunks (generated by Google Gemini Embeddings) along with chunk metadata for similarity search.
2. **PostgreSQL (Relational Tables)**:
   - Stores application records: `documents`, `ingestion_jobs`, `conversations`, `messages`, `nlp_analytics`, `retrieval_analytics`, `citation_analytics`, and `llm_analytics`.
3. **Local File Storage (`uploads/`)**:
   - Stores raw uploaded files on disk (`.pdf`, `.txt`, `.md`), enabling users to stream or download original source files via `/api/documents/{id}/file` and `/api/documents/{id}/download`.

---

## 3. PostgreSQL + pgvector Setup

### 3.1. Docker Compose Configuration

A ready-to-use Docker Compose configuration is available in `deployment/docker-compose/docker-compose.yml`:

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg17
    container_name: ai-chat-postgres
    environment:
      POSTGRES_DB: ai_chat
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  postgres_data:
```

### 3.2. Start PostgreSQL Container

```bash
docker compose -f deployment/docker-compose/docker-compose.yml up -d
```

### 3.3. Verify Database and Extensions

```bash
docker exec -it ai-chat-postgres psql -U postgres -d ai_chat -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

## 4. Environment Variables & Configuration

The application is configured in `backend/src/main/resources/application.properties`:

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `GEMINI_API_KEY` | **Yes** | None | Your Google Gemini API Key. |
| `POSTGRES_PASSWORD` | No | `postgres` | Password for PostgreSQL user. |
| `STORAGE_UPLOAD_DIR` | No | `uploads` | Directory on disk where raw uploaded files are stored. |
| `NLP_MOCK_ENABLED` | No | `true` | `true` uses deterministic internal mock; `false` calls external NLP service. |
| `NLP_SERVICE_URL` | No | `http://localhost:8000/api/nlp/analyze` | External NLP microservice endpoint. |

## 5. Building and Running the Application

### 5.1. Run Automated Tests

**Linux / macOS**:
```bash
./mvnw clean test
```

**Windows**:
```powershell
.\mvnw.cmd clean test
```

### 5.2. Start the Spring Boot Backend

**Linux / macOS**:
```bash
./mvnw spring-boot:run
```

**Windows**:
```powershell
.\mvnw.cmd spring-boot:run
```

---

## 6. Document Ingestion Lifecycle & File Access

1. **Upload Document**:
   ```bash
   curl -X POST http://localhost:8080/api/documents \
     -F "file=@/path/to/document.pdf"
   ```

2. **Check Ingestion Status**:
   ```bash
   curl http://localhost:8080/api/documents/{documentId}/status
   ```

3. **Preview / Stream Original File in Browser**:
   ```http
   GET http://localhost:8080/api/documents/{documentId}/file
   ```

4. **Download Original File**:
   ```http
   GET http://localhost:8080/api/documents/{documentId}/download
   ```

## 7. Testing the Chat QnA API

```bash
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "What is the return window for items?"}'
```

---

## 8. Switching from Mock NLP to Real NLP Microservice

Set `NLP_MOCK_ENABLED=false` and provide `NLP_SERVICE_URL` to point to your live microservice.
